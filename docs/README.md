## 文档特性

### ✅ 所有文档的共同特点

- **跨平台**: 适用于 Linux、WSL、macOS
- **无硬编码**: 使用相对路径，可在任何目录工作
- **实用性强**: 包含可直接执行的命令示例
- **故障排查**: 每个文档都包含常见问题解决方案

### 📝 文档更新策略

- **主文档**: README.md, fabric开发.md（随功能更新）
- **配置文档**: 跨平台配置*.md（配置变更时更新）
- **参考文档**: 快速参考卡.md（保持简洁，定期精简）

## 快速命令

### 阅读特定主题

```bash
# 在终端中快速查看
cat docs/快速参考卡.md

# 搜索特定内容
grep -r "Docker" docs/

# 在浏览器中查看（如果是 Markdown 渲染的）
open docs/README.md  # Mac
xdg-open docs/README.md  # Linux
```

### 生成文档目录

```bash
# 列出所有文档
ls -lh docs/

# 按时间排序
ls -lt docs/ | head -10

# 按大小排序
ls -lS docs/
```

## 文档维护

### 更新检查清单

当项目发生以下变更时，需要更新文档：

- [ ] 添加新功能 → 更新 README.md
- [ ] 修改配置文件 → 更新 fabric开发.md
- [ ] 添加新脚本 → 更新 scripts/README.md
- [ ] 修改路径配置 → 更新跨平台配置*.md
- [ ] 发现新问题 → 更新故障排查章节
- [ ] 支持新平台 → 添加新的配置指南

### 文档质量标准

每个文档应包含：

- ✅ 清晰的目录结构
- ✅ 实用的代码示例
- ✅ 常见问题解决方案
- ✅ 跨平台考虑
- ✅ 最后更新日期

## 贡献文档

### 如何贡献

1. 发现文档错误或不清楚的地方
2. 创建 Issue 或直接提交 PR
3. 遵循现有文档的格式和风格
4. 确保示例代码可以实际运行

### 文档风格指南

- 使用 Markdown 格式
- 代码块指定语言（```bash, ```yaml, etc.）
- 使用 emoji 增加可读性（适度）
- 中英文混排时注意空格
- 保持简洁，避免冗余
